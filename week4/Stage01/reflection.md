# Part G - Improve One Thing

## Selected Improvement
I chose to prevent the program from accepting a blank patient name.

## Reason


A patient name is required for an appointment. This check prevents an appointment from being created if the patient name is left blank.

# Part H - Reflection

Before using AI, I used the code provided in the lab to build a basic SmartCare appointment booking prototype. The code stored information such as the patient name, practitioner name and appointment time. It also helped me understand how lists, dictionaries and functions can be used in Python.

AI helped me understand another way of creating the appointment booking system. It showed me how the program could ask the user for appointment information through the terminal instead of having the information already written in the code.

The AI made some assumptions when creating the alternative version. For example, it assumed that any information entered by the user was valid and did not originally check for blank inputs.

I verified the AI output by running the code in PyCharm and entering different test inputs. I tested normal information, blank information and unusual information to see how the program responded.

There was still engineering work that I needed to do myself. I had to test the AI-generated code, identify its problems and decide what improvement should be made. I chose to improve the program by rejecting blank patient names. This helped me understand that AI can provide different solutions, but I still need to test and understand the code myself.
